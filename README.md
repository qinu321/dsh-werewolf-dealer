## 1. 接口一览

两层接口，**互不替代**：AI 席位只能调工具（`wolf_*`，模型侧），人类只能敲命令（`/ww-*`）。
工具里没有管理对局的能力（暂停/终止/收票都不给模型），命令也不能被 AI 会话调用。

### 1.1 AI 侧工具（模型可调）

| 工具 | 谁用 | 干什么 |
|---|---|---|
| `wolf_speak` | AI 玩家 | **白天发言 / 投票 / 赛后的完赛感想**都走它：只交正文，房间、`【R{轮}-{序号} · 别名】` 前缀与「唤醒下一位」的提及全由庄家算。没轮到你时会被拒；**没有你参与中的对局时一个字都不发**（局外想往房间说话用 `chat_send`）。 |
| `wolf_reply` | AI 玩家 | **夜间的私下回答**（验人 / 换卡）与**确认阶段的「是」**：只在庄家私聊问你时用（庄家只按固定模板处理、不回答提问）。**庄家的回话（读数 / 换卡结果 / 复问）直接出现在这次调用的返回值里** —— 看返回值，别去轮询收件箱。 |
| `wolf_status` | 任何人 | 查**公开**状态：局号 / 阶段 / 轮次 / 当前该谁发言 / 已收票数，**不含任何身份信息**（夜间连 `nightStep`/`awaiting` 都不给 —— 那会唯一确定谁是真预言家）。观察员命令 `/ww-status` 才有完整字段。 |
| `wolf_start` | 观察员或受委托的会话 | 开一局：广播开局 + 逐位私聊发牌。**牌面由庄家随机发** —— 钦点「谁拿哪张角色卡」是观察员 `/ww-start` 的专属参数（且只在纯 AI 局可用），本工具没有这个能力。 |
| `wolf_pause`（**默认关闭**：`aiPauseTool: true` 才注册） | AI 玩家 | 发现无法处理的异常时**立刻暂停本局并写下理由**：理由进观察员的浮层信箱 + `ai-pause` 审计，**不进房间**。**单向阀门** —— AI 只能停、不能恢复（`/ww-resume` 是人的权力）；理由必填。 |

### 1.2 人类侧命令（`/ww-*`）

「谁用」一栏：**观察员** = 人类观察员；**真人** = 参战的人类席位。真人日常只有 `/ww-reply`、`/ww-status`、`/ww-inbox` 用得到，其余都是观察员的权力。

| 命令 | 谁用 | 干什么 |
|---|---|---|
| `/ww-start <房间> <3\|4\|5\|6> <席位…> [seed=数字] [<座位号\|席位名>=<角色卡> …]` | 观察员 | **开局**。`seed=` 便于复盘复现；纯 AI 局还可**钦点牌面**（`1=狼`、`大D=预言家`，角色卡只有 村民/预言家/怪盗/狼）。复盘写手结算时才定，不能用参数指定。 |
| `/ww-reply <回答>` | 真人 | **回答庄家**的夜间提问与确认（`2`、`验 大D`、`换 小米`、`不换`、`是`）：只发给庄家，不进房间；也可以直接点弹窗卡上的按钮。 |
| `/ww-status [房间名]` | 观察员 / 真人 | 查对局**当前状态**：阶段、轮次、该谁发言、收票进度。若庄家正在等你回话，会**直接贴出待答原文** —— 这是真人能看到"庄家在等我"的唯一主动通道。 |
| `/ww-pause [房间名]` | 观察员 | **暂停**本局：停止推进与唤醒（公告照发，但不叫醒任何会话）；恢复只能用 `/ww-resume`，AI 没有这个键。 |
| `/ww-resume [房间名]` | 观察员 | **恢复**暂停的对局，从停下的那一步继续。 |
| `/ww-nudge [seat=<座位名\|座位号>] [房间名]` | 观察员 | **手动催**该动的人（夜间等回复者 / 白天该发言者 / 投票期未投者），报告里带每个被催会话的实时状态。没有计时器：你不按它就不催。也可直接 `/ww-nudge <座位名>`（先当房间名解析，不存在再当座位名）。**`/ww-night` 是它的旧名**。 |
| `/ww-close-day [lost=<失联席位>] [房间名]` | 观察员 | **白天到此为止**：放弃当前轮剩余发言 + 之后所有轮次 + 确认阶段，直接开票。`lost=` 标记的席位仍是本局席位（计票/结算/代投不变），但此后**不再被点名/催票/赛后点名**。⚠ 与 `/ww-void` 不同：那个是"本轮作废、重来"。 |
| `/ww-void [房间名]` | 观察员 | **作废当前发言轮并重来**（仍在白天）。⚠ 只重来、不进投票 —— 要跳过剩余发言直接开票用 `/ww-close-day`。 |
| `/ww-close-vote [房间名]` | 观察员 | **截止收票并结算**（缺票者按规则记弃票）；在**确认阶段**则等于跳过等待、直接开票。 |
| `/ww-override-vote <座位> <目标\|平安夜>` | 观察员 | **替已公开声明的席位补那一票**；补齐最后一票即自动结算。⚠ 不接受 `弃票`（未声明者请用 `/ww-fill-abstain` 代记）。 |
| `/ww-fill-abstain [房间名]` | 观察员 | 把**所有还没投票**的席位一次性记为**弃票**（只在投票阶段用）—— 玩家自己投不出弃票了，这是产生弃票的入口。 |
| `/ww-recount [房间名]` | 观察员 | **重算并显示当前票型**（谁投了谁 / 还差谁 / 最高票与并列），**不改任何状态**，只在审计里记一笔。 |
| `/ww-end [--void] [房间名]` | 观察员 | **提前终止 = 作废本局**：房间只发中性通知，身份表与参考结算只私聊回执行命令的会话；**不写 raw、不占局号、不算复盘写手**（`--void` 是等价别名，只在审计留标记）。 |
| `/ww-audit [房间名]` | 观察员 | 查看本局**完整审计**（含牌面 / 夜聊原文：文件路径 + 前 40 条，多的自己读文件）：只回给你，**绝不进房间**。审计是只增的 ⇒ 与状态文件不一致时**以审计为准**。 |
| `/ww-inbox [房间名]` | 真人 | **取回**庄家发给你的夜聊原文（发牌 / 同伴 / 提问 / 读数 / 换卡结果）—— 官方 UI 不渲染庄家私聊，真人靠它看牌与回答。 |
| `/ww-sessions [关键字]` | 观察员 | 列出**可绑定为私聊信道的会话**（标题 + 会话 id + 在线状态；重名标题带 ⚠），绑定时用会话 id 最稳。 |
| `/ww-config` | 观察员 | 查看**当前生效的配置**与目录可用性（每个值的来源、目录是否存在、下一个局号是第几局、投票限时是否关闭）；改完配置重启后用它对账。 |

> **这些命令也能直接打在房间发言框里**：庄家在消息落盘之前拦下执行并**吞掉这条消息**（房间时间线不留痕、AI 也看不见），回执走屏幕正中的浮层弹窗。依赖 dsh-chat 补丁 21 —— 没有它插件不会在房间里拦命令（拦了也白拦），并且会拒绝「弹窗模式」开局。

**席位写法**（`/ww-start` 与 `wolf_start` 通用）：

| 写法 | 解析范围 | 含义 |
|---|---|---|
| `大D` | **只看房间成员**（别名或会话 id，必须唯一命中） | 该成员会话就是它的私聊信道（AI 席位） |
| `大D=<会话标题或id>` | ① 精确会话 id（活着的+已落盘的都认）→ ② **活着的**会话按标题 → ③ 退回桥接层 | 显式绑定私聊信道 |
| `*千野` | 房间成员（不唯一即报错） | 真人席位 |
| `*千野=<会话标题或id>` | 同上 | 真人席位 + 私聊信道 |

> **重名怎么办**：不带 `=` 的写法只在房间成员里查别名（重名 → 报"命中 n 个"）；
> 带 `=` 的写法**先按会话 id 精确匹配**，再在**活着的会话**里按标题匹配（标题命中多个 →
> 拒绝并列出全部候选 id）。所以会话 id 永远是无歧义的那把钥匙：重名环境下用 `/ww-sessions`
> 查出 id，写成 `*千野=<会话 id>`。
>
> ⚠ **本机实测的一个第三方故障（2026-10-04），已打本地补丁**：dsh-bridge 的**标题**分支曾是坏的——
> 它调 `sessionProjectionCache.cachedSnapshot(header, 0, ['title'])`，而本版本该方法是
> `cachedSnapshot(meta, keys)` 两参 ⇒ `keys = 0` ⇒ 内部遍历数字 0 ⇒
> `number 0 is not iterable (cannot read property Symbol(Symbol.iterator))`。
> 本插件因此**自己解析标题**（只针对活着的会话，标题权威来自 `sessionTitle`），并把那条已知错误
> 翻译成"请改用会话 id"的可执行提示（即使桥接层以后再漂移，也不会把原始 TypeError 漏给你）。
> 同时已给 dsh-bridge 打**本地补丁 6**（去掉那个遗留的 `0`；改前改后 SHA 与回滚步骤见
> `.dsh-plugin-backups/PATCH-NOTES-dsh-bridge.md`），所以**离线会话按标题绑定**在重启后也可用。
> 注意该补丁随 dsh-bridge 升级/重装丢失，重打看同一份 patch notes 的补丁 6。

**通信信道**

- 房间广播 → `ctx.dshChat.chat.send({ roomId, author: 'werewolf-dealer', authorAlias: '庄家', text, mentions })`。
  纯发布不需要先加成员：`room-store.js#send` 只按 `room.members` 解析提及与投递。
- 夜间私聊 → `ctx.dshBridge.deliverExternal('werewolf-dealer', <玩家会话 id>, text, { transport:'werewolf', wake })`。
  只投给该玩家的会话，其他玩家会话不可读（§8.3）。`:wake` 对 AI 席位为 `true`（唤醒它来回答），
  对**真人席位为 `false`**（只落到他自己的会话时间线，不触发该会话的模型回合）。
- 房间消息入站 → `ctx.dshChat.chat.subscribe(...)` 的实时事件流。

**用法写给谁（为什么规则卡里不需要提本插件）**

规则卡是**游戏规则**的权威（怎么玩、怎么判胜负），本插件是**平台接口**（怎么投递、怎么回话）。
接口细节不进规则卡，原因有三：① 规则卡每局都要读，写平台细节等于让游戏规则跟着插件版本漂；
② 规则卡是"玩家读的文档"，而玩家需要通道信息的那一刻是**夜里收到提问的那一秒**，不是开局读文档时；
③ 玩法改动（比如以后换回话工具）会让规则卡变成假话。

本插件的做法是**把通道写进需要它的那一条消息**（§9 模板约束内，只加不改语义）：

| 席位 | 收到的提问会附 |
|---|---|
| AI 席位 | `（用 wolf_reply 工具把回答发给我；直接在自己会话里说话我收不到。）` |
| 真人席位 | `（私人信道：直接在本会话输入 /ww-reply <你的回答>；…）` |

模型工具表里本来就有 `wolf_reply`，但"用自己的话在自己会话里回一句"是更自然的默认动作，而庄家收不到那句话
（夜序会卡住）—— 所以提示必须挂在提问当场。投票格式同理，写在收票公告里。

> 数值会被夹到有效范围：`reminderMs ≥ 0`、`appealReplayLines ≥ 0`、`voteDeadlineMs ≥ 0`、`voteGraceMs ≥ 0`。
>
> 说明：本插件是零依赖的链接安装包，**不能** `import` `@deepseek-ai/schemastery`（从插件真实路径解析不到，
> 会导致加载失败），所以它**不导出 `Config` schema** —— 也就不出现在 GUI 的表单式设置里，配置以
> 「profile 补丁层的 YAML + `/ww-config` 核对」的形式暴露。这是刻意的取舍，不是漏做。

> 如果将来确实想要自动催，判据不该是时间，而是 **`ctx.dshBridge.status(会话).state`**：
> 只有当前应发言者处于 `idle`（真的没在跑）才提醒，`running`（在思考）永不打扰。
> 即便如此，也仍建议保留"由人判断"的手动催 —— 状态判定不了"它是不是正在写但没投递"。

## 3. 一局怎么跑

**人数与牌堆（规则卡 §总卡数，v1.13.0 起支持 3–6 人；7 人及以上没有规则 ⇒ 拒绝）**：
**总卡数 = 人数 + 2**（未分配的那 2 张正好给预言家选项②看），狼恒 2 张、预言家 1 张、怪盗 1 张，
其余按人数补村民（村民 = 人数 − 2）：

| 人数 | 总卡数 | 狼 | 村民 | 预言家 | 怪盗 | 未分配 |
| --- | --- | --- | --- | --- | --- | --- |
| 3 | 5 | 2 | 1 | 1 | 1 | 2 |
| 4 | 6 | 2 | 2 | 1 | 1 | 2 |
| 5 | 7 | 2 | 3 | 1 | 1 | 2 |
| 6 | 8 | 2 | 4 | 1 | 1 | 2 |

**胜负（规则卡 §游戏胜败；结算按换卡后的现值算阵营）**：最高票者是狼 ⇒ 人类胜；是人类 ⇒ 狼胜；
并列最高票恰为**两位玩家**（2:2 / 3:3 / 2:2:1…）⇒ 两人都淘汰，其中有狼则人类胜，两人都是人类则人类败；
**平安夜**与某玩家并列最高 ⇒ 按淘汰那名玩家算；**三方及以上并列**（含 平安夜:1:1:1）⇒ 无人淘汰，
有狼则狼胜、无狼则人类胜；**全场弃票 ⇒ 算做平安夜**（v1.13.1 起，用户口径）：按「场上有没有狼」判胜负
（结算正文仍会列出「（无有效票）+ 弃票名单」，看得出这是弃票而不是真投了平安夜）。
⚠ **弃票本身不是票值**（v1.25.0 起玩家可**主动**投出，不再只有"等超时"一条路）：它不进计票表 ⇒
**不参与任何并列判定**，也不与平安夜等价 —— 只有"全场都没有有效票"时才落到上面那条平安夜分支。
⚠ 特别分支：**场上已无狼，却把一名人类投了出去** ⇒ 按规则卡算**人类阵营失败**（误杀同伴），
结算语会直接这么写，而不是笼统地说「狼阵营获胜」。

1. 人类观察员把玩家会话拉进房间（`chat_create` / `chat_invite`），确保每位玩家的**房间别名**就是座位名。
2. `/ww-start AI狼人杀3 4 大D 小米 大G 小鲸鱼`（可选 `seed=数字` 便于复盘复现；**复盘写手不能用参数指定**，结算时才定 —— v1.8.0 起 `writer=` 已删）。
   - **v1.35.0（纯 AI 局专用，人类观察员专属）**：还可以直接钦点牌面 ——
     `/ww-start AI狼人杀3 3 4B 小米 问候大D 1=狼 2=预言家`。`<座位号|席位名>=<角色卡>`，
     角色卡只有 **村民 / 预言家 / 怪盗 / 狼**（`1:狼` 也认；`1:狼人` 这种写错会被拦下）。
     **含真人席位一律拒绝**；没钦点的席位与牌堆仍按 `seed` 抽；牌堆算术不够（3 人局要 3 张狼）同样拒绝。
     承诺哈希与结算【对账】照旧 = 真实发出的牌的哈希（钦点不改变可验证性）。
3. 庄家自动：广播开局（**v1.16.8 起带「开局承诺」、v1.16.9 起加盐**：全量状态＝各座位**发到的牌 + 牌堆**的
   `sha256(盐 + 换行 + 规范串)` 前 16 位；**盐开局不公开** —— 牌面空间只有 60~840 种，无盐哈希能被**穷举反推**
   （本机实测 4 人局 21 次即破），盐在结算时随牌面一起公布 ⇒ 届时谁都能重算对账。换卡只改**现值**、不改承诺对象）→
   **发牌只发给狼与村民**（狼那条里并着同伴信息；**v1.7.4 起怪盗/预言家不另发牌**，
   它们的身份由夜序提问承载）→ 夜序 `预言家 → 狼 → 怪盗`（预言家/怪盗逐条提问、等回复再进下一位；
   **狼步不投递**，只推进）。玩家在**自己的会话**里用 `wolf_reply` 回答（例：`2` / `验 大D` / `换 小米` / `不换`）——**结果就在这一次工具调用的返回值里**（v1.16.13 起，见下表「哪些通知不唤醒」）。
4. 夜里全部走完，庄家广播白天开场（`mentions = ["all", 首位发言者]`，只唤醒第一位）。
   ⚠ **庄家只在"开局"与"开投票"两处自己 AT 人**：之后唤醒下一位的提及挂在**上一位发言者那条消息**上。
   v1.16.5 起发牌与开场广播都直写「**被唤醒就是轮到你**，不要等庄家的单独提醒」（v1.20.1 把"被 @"改成"被唤醒"）—— 2026-10-05 第 8 局实测：
   第 2 轮首位的 AI 被上一位（真人）正确 @ 到，却坐着等"庄家的 AT"，把整局停住。
5. **白天发言走 `wolf_speak`（v1.9.0 起）**：AI 席位只把**正文**交给工具 —— 前缀 `【R{r}-{序号} · {别名}】`、
   「唤醒下一位」的 `mentions`、以及房间本身（`game.roomId`）全部由庄家按自己的轮次/序号算，
   模型不写前缀、不填 mentions、不指定房间：

   | 情形 | 庄家代投时的 `mentions` |
   | --- | --- |
   | 一般席位（含**第 1–4 轮的末位**，跨轮循环） | `["all", 下一位别名]` |
   | 第 5 轮末位（全场最后一位） | `["all"]`（没有下一棒；**v1.27.1 起也不再由它召集**，见下） |
   | 下一位是**真人** | `["all"]`（点名对真人无效；他靠房间发言框上的前缀条知道轮到自己了） |

   ⚠ **召集（`["all", …全部 AI 席位]`）由谁发（v1.27.1）**：**确认提问**（以及开票公告、结算公告）发；
   **末位发言不发** —— 原先"末位发言也召集"会让紧随其后的确认提问**必然落在 `inject`**（目标全在跑），
   于是那条提问收得到、却在 AI 会话里**没有可见行**。挪走召集后提问到达时全员空闲 ⇒ 会话里看得见，且少一次全员唤醒。

   没轮到你时调用会被**拒绝**（写明现在该谁），房间不会多出任何消息。
   ⚠ **`wolf_speak` 是狼人杀专用工具**（v1.16.1 起在工具说明里钉死）：白天发言、投票、赛后的完赛感想
   都用它，但它**只在局内有效** —— 没有你参与中的对局时它**一个字都不发**（只回一句原因）；
   那种情况（或想在局外往房间发消息）要用 `chat_send`。房间/作者/提及也全由庄家定，自己填白填。
   **真人在房间里只打正文**（v1.10.0 起）：庄家**接管了房间发言框** —— 他打的那条在**落盘之前**
   就被补上前缀与正确的提及，房间里自始至终只有**一条**规范版（不存在「先发出来、再删掉」）。
   发言框上方会显示一条只读前缀（`【R1-1 · 名字】` + 点名对象），**那只是提示**：发送时交上去的仍是正文，
   改写由服务端完成 —— 所以提示偶尔慢半拍也不会写坏消息。
   接管只在「白天 + 正轮到他」时生效；**投票、上诉、不在他轮次的消息一律原样发出**。
   旧写法（AI 用 `chat_send` 自己写前缀、自己 AT）仍然收得住，作为兜底保留。
   该能力依赖 dsh-chat 的**补丁 20**（没装时插件启动会记一条 warn，手写前缀的老办法照旧可用）。
   庄家只做判定，不对正常发言做任何回应。
6. **命令也能在房间里打（v1.11.0 起）**：`/ww-start`、`/ww-status`、`/ww-nudge`、`/ww-reply`、`/ww-end`
   …… 所有 `/ww-*` 都可以直接打在**房间发言框**里。庄家在消息落盘之前把它拦下执行、**吞掉这条消息**
   （房间时间线上不留痕、AI 也看不到），回执走**屏幕正中的浮层弹窗**（v1.16.6 起居中，此前在右下角）。
   这一步依赖 dsh-chat 的**补丁 21**（`supportsComposerConsume`）；没有它插件**不会**在房间里拦命令
   （拦了也白拦，命令正文会当众发出去），并且会拒绝「弹窗模式」开局。见 §3.5。
6. 5 轮走完，庄家广播收票（同一条消息 `mentions = ["all", 全部玩家]`：进时间线 + 逐个唤醒），
   玩家发 `投票：<名字>` 或 `投票：平安夜` —— **AI 席位用 `wolf_speak` 交正文就行**
   （v1.15.1 起投票阶段也认这个工具；本来也该走 `chat_send`，但 AI 用顺手的是前者，搞错命令会卡在收票阶段）。
   ⚠ **一票落定不可撤改（v1.18.0）**：票是**公开**投在房间里的 —— 若允许重发覆盖，长回合的 AI 就能
   **看着别人的票再改票**。现在**首投为准**：同内容重发 = 幂等回执（不重复投递、不重复计票）；
   内容不同（或认不出） = 拒绝且**不进房间**（房间不留第二只气泡）。要改票只能由观察员 `/ww-override-vote` 覆盖。
   ⚠ **投票阶段不计时（v1.30.0）**：新规则卡去掉了投票限时，而"超时自动记弃权"正是主动弃票的变相入口
   ⇒ `voteDeadlineMs` 恒为 0：不催票、不判弃权。收票停在"缺票"状态时由观察员 `/ww-close-vote` 收口
   （缺票者按规则记弃票），或用 `/ww-fill-abstain` 一次性代记；想手动催人仍有 `/ww-nudge`。
   （旧行为 v1.19.0–v1.29.x：2 分 30 秒先催、再宽限 2 分 30 秒，合计 5 分钟窗口，超时记弃权 —— 只在本配置 > 0 时恢复。）
   ⚠ **禁止自投（v1.20.0）**：投给自己的票**判无效、要求重投**（与主流狼人杀一致，用户 2026-10-06 定）。
   AI 走 `wolf_speak` 时**在投递前就拦下**（房间不留气泡、工具回执直接给"不能投给自己 + 可选座位"）；
   回流路径（`chat_send`／真人在房间里打字）判无效并**私下让本人重投**（不告知的话他会以为投过了）。
   ⚠ 自投**不落定**（重投照常算）；已落定之后再发自投 ⇒ 走"不可撤改"，不再复问。
   选它的依据（5 人局全枚举，见决策表）：三档里"禁止自投"**不会消灭任何判决类型**，也不像"自投算弃票"那样让票凭空消失。
   ⚠ **不能弃票（v1.30.0，与 v1.25.0 的口径相反）**：新规则卡「非失联者不得弃票/弃权」⇒ 写「弃票」「弃权」
   「不投」（行首）一律**打回重投**（不落票、不锁票），并私下告诉你可选目标。**投票卡上也没有「弃票」按钮**。
   弃票这个票值只剩两条来源：观察员代记（`/ww-fill-abstain`）与续局的旧状态。
   ⚠ 它**不进计票表** ⇒ **不当并列方**（`平安夜`是普通票值，会与某玩家票数并列 ⇒ 按 §5 淘汰那一人）。
- **浮层可拖动、背景改用 overlay token（v1.16.11）**：庄家私聊浮层（v1.16.6 起屏幕正中）
  **按住标题栏即可拖动**（指针捕捉，跟手到松手）；背景从 `--dsw-alias-bg-layer-1` 换成官方
  **`--dsw-alias-bg-overlay`**（与"弹出来问你"的那种框同浓度）——半透明皮肤下压着对话也能看清字。
  只动 `client.js` ⇒ **刷新页面即生效**，不用重启。
- 真人则点弹窗里的 `投 ×××` / `投 平安夜` 按钮（v1.15.0 起；**弃票按钮 v1.30.0 起已删**），或照旧手打。
   中间任何一环卡住（典型如某个 AI 把"下一位"记错人，唤醒错了会话、该说话的人没被叫醒），观察员敲
   `/ww-nudge` 手动催一次即可 —— **没有计时器**，你不按它就不催；报告会列出被催者的实时状态，
   `正在运行` 说明它多半只是在长思考（本机 mimo 可为一句发言想 54 分钟），别重复催。
7. 全员到齐或观察员 `/ww-close-vote` ⇒ 结算公告（逐票统计、身份表、牌堆、胜负、**复盘写手** ——
   **v1.27.2 起公告点明落点**（v1.34.1 起文案为「**方法论**中的复盘由 X 来写」）；单局详情由插件自动导出 raw、不再由 AI 写，
   写手只往方法论（`E:\codeVibe\group\狼人杀方法论.md`）落方法论/机制/判据，
   以及 **v1.16.8~v1.16.10 的「【对账】」段**：开局承诺哈希 + **该承诺的盐** + **承诺原串**（照抄即可复算，
   v1.16.10 起 —— 上面的牌堆行是分类计数、丢了原序，只给哈希+盐会让复算失败、看着像"牌被改过"）
   + **夜序记录哈希** —— 夜序原文与它的盐都不公开、只给哈希防事后改写，对私信真伪有争议时由第三方定向核对），
   同时把 raw 记录写到 `狼人杀复盘\_raw\<YYYY>\<MM>\<YYYYMMDDHHMM>_第X局.md`（自动按日期建子目录，局号自增不覆盖；**文件名里的时间戳 = 开局时刻**，v1.16.7 起）。
   写手在**这一步**才定（开局不指定，v1.26.0 重定规则）：**双方人数不等 ⇒ 人少那一方里顺位最后的 AI**；
   **人数相同 ⇒ 全场顺位最后的 AI** —— 白天是固定环形顺序，所以"顺位最后"就是"最后发言"（真人不当写手）。
   写手的**落点**（v1.27.2 定为项目笔记；v1.34.1 起改为**方法论**：`E:\codeVibe\group\狼人杀方法论.md`），
   只收方法论/机制/判据；单局详情看 raw，别再写一份日志（**项目笔记不再收复盘**）。
   **赛后**：你说的第一条会「点名全场」（参赛时由你的席位发出、AI 局里你就是观察员）⇒ 唤醒 AI 回话
   → 「## 完赛感想」，raw 随之重写。**AI 席位至多两条**进这一节（结算后自动发的感想 + 你点评之后那条回复），
   真人一条。⚠ **公告文案故意只写"每人只收第一条"**（v1.28.1）：写明"至多两条"会让 AI 结算后
   **当场把两条都用光**，你的点评就没人回。

### raw 长什么样（v1.8.0 起；v1.16.0 追加「## 完赛感想」）

文件结构：标题 + bullet 元信息 → `## 牌面` → `## 白天发言链判定` → `## 票型与结算` → `## 完赛感想`。
**「## 白天发言链判定」与「## 完赛感想」两节**是 Obsidian
[Chatbox](https://github.com/qinu321/Chatbox-for-Obsidian) 气泡卡：该节第一行是
`> [!chatbox|<chatstyle>-long[-swap]]+ …`，之后逐条气泡 ——
AI 是 `> - ![face](头像) \`名字\` 正文`，真人是 `> + …`。
白天那一节：每轮先一段旁白（`> ` 空行 + `> 2026-10-04 12:22:02 round 1`），方向切换的那一轮旁白后补一个
隐形行 `> \n> <span></span>`（Chatbox 靠它把下一段气泡摆到另一边）；`-swap` 的判据是
**第一句发言是 AI 就加**（那一节开头是旁白，AI 实际是第二句，所以要 swap 才摆得对）。

**「## 完赛感想」**（v1.16.0 起；v1.16.2 改了触发方式；**v1.28.0 改上限与顺序、v1.28.1 回调公告文案**）：
**你在赛后说的第一条会「点名全场」**（正文一个字不改，只有提及由庄家补成 `["all", …全部 AI]`）——
你一句「这局……」就把所有 AI 唤醒，他们顺着回话、顺便把感想说了（AI 的感想只 `@all`，不会互相叫醒）。
这条逻辑**参赛与观战通用**（v1.16.3）：你是玩家时它由你自己的席位发出；**AI 局里你是观察员**，
你的点评同样会点名全场 —— 而且**你的点评也会进这一节**（v1.16.4）：它是这一节的**真人行**
（`+`、头像取「你」、名字用配置里的 `humanName` 兜底）。
**条数（v1.28.0）**：**AI 席位至多两条**（结算后自动发的感想 + 点评之后那条回复），
**真人只收一条**（观察员同样一条）；超出的发言照旧落房间，只是不进这一节。
⚠⚠ **公告文案与这里的额度是故意不一致的（v1.28.1）**：`T.closingOpen()` 只写「每人只收第一条」，
因为**写明"至多两条"会让 AI 在结算后当场把两条都用光**（用户真机实测），之后你的点评就再没人回 ——
而那条回复恰恰是要收进复盘的。同理，额度用满时的拒绝理由只回「你赛后的发言名额已满」，
**不报真实条数**。⇒ 以后**不要**"顺手把文案改成和实现一致"。
收一条就**重写同一个 raw 文件**，所以这一节在结算时还不存在、之后陆续补上。
⚠ 庄家**不发**任何感想邀请；那次「点名全场」**一场只用一次**（第二条起不再点名，免得每句都叫醒全场）。
**顺序（v1.28.0）**：**AI 首轮（按座位）→ 真人（按座位，无座位的观察员最后）→ AI 次轮（按座位）** ——
复刻房间里的真实时序（AI 先自动发感想 ⇒ 你点评 ⇒ AI 回第二条）；同档内不看到达顺序、只看座位。
**callout 头（v1.28.0）**：这一节固定是 `> [!chatbox|<chatstyle>-long]+ 感想`，**不再带 `-swap`**
（白天那一节的 `-swap` 判据不受影响，仍是"第一句是 AI 就加"）；头像同样取 `avatarFile` 的同名键（真人取 `你`）。
没有任何感想 ⇒ **整节不出现**。

- 时间一律**本地时间** `2026-10-04 12:22:02`（早期版本用了 UTC 的 ISO，比本地差 8 小时）；
- 气泡里是**发言正文本身**（前缀 `【R1-1 · 名字】` 已剥掉，`\n\n` 会变成同一气泡里的真换行）；
- 续行开头若是**有序列表**（`1.`／`2)`）、**标题**（`#`）、**嵌套引用**（`>`）、**加号**（`+ `）、
 **星号**（`* `，后面跟空格才算）会被**转义一个反斜杠**（`1\. `／`\+ `／`\* `），
 否则 Obsidian 会把气泡当场截断，或把方向**翻边**（`+ `/`* ` 都是 Chatbox 的方向标记，
 会造成一个"没名字没头像"的气泡）。转义只加反斜杠，**渲染出来与原文一字不差**；
 ⚠ `*斜体*`、`**粗体**`（星号后面不跟空格）是正文样式，**不转义、原样保留**；
- 但 `- ` **故意不转义**：`> - 破折项` 在 Chatbox 里会渲染成**一个独立气泡**跟在对话后面，
 正好起分段作用（转义成 `\-` 反而只在气泡里戳一个孤零零的减号）；
- 头像取 `avatarFile` 的**同名键**（真人取 `你`）；读不到就不写 `![face]`；
- 只画**被接受**的发言，被拒/作废改画成旁白式的提示行，不污染对话；
- 头部元信息、`## 牌面`、`## 票型与结算` 都**保持原有形态**（不在 callout 里）；
- **不再有**「夜间（发牌/夜聊原文/读数/换卡）」与「全量事件」两块机器数据。
- 「## 完赛感想」是**事后重写**补上的：写完 raw 之后收到的第一条感想会触发同文件重写（路径从审计里的
  `export` 记录取，重启进程也找得到）；写盘失败只记 warn，感想仍在对局状态里，下一条到达时再试。

房间里有**整句**的「申请庄家裁定」（可以接理由）、或整条只有「上诉」两个字时，庄家受理上诉：
**默认只回一行回执**（`appealReplayLines: 0`，v1.28.2 起）；把 `appealReplayLines` 设成 `>0` 才会
额外回放 N 条**脱敏**审计片段（只回放不含牌面的记录）。完整审计（含牌面）始终落在
`<stateDir>` 里，观察员用 `/ww-audit` 自己看。

⚠ 判据是**整句匹配**（v1.28.2 起）：`不上诉`、`撤回上诉`、正文里顺口提一句「上诉」都**不会**触发
—— 旧实现的包含匹配曾把小米的一句「裁决收下，不上诉——」判成上诉，回放刷屏**且那条发言没被记成发言**，
整局就停在他那一棒。

## 3.5 真人下场怎么玩（v1.11.0 起：**不需要信箱会话**；v1.12.0 起一句话开局）

**最快的开局方式（v1.12.0）**：房间**发言框那一排的最右边**有 `开局` 按钮 + `真人`、`随机` 两个勾选框
（需要 dsh-chat 补丁 22）：

- 直接点 `开局` = 按**房间当前成员数**开一局纯 AI（**少于 3 人拒绝**；3–6 人可用，7 人及以上没有规则 ⇒ 拒绝）；
- 勾上 `真人` = 把你（名字由配置 `humanName` 定，默认「玩家」）也加进去一起玩；
- 勾上 `随机` = 随机排发言顺序（默认按成员加入房间的顺序）。

失败原因（人数不够 / 超编 / 房间已有对局…）会以红字显示在发言框里；开局成功则房间会广播顺序。
有进行中的对局时这排控件会收起来 —— 要改开局参数就先 `/ww-end`。

**老房间（冷存、只读）里没有这排控件**（v1.13.2）：老房间只是归档（`MAX_LIVE_ROOMS = 1`，同一时刻只有
一个活跃房间），它连发言都收不下（dsh-chat 的 `send()` 会直接拒绝），所以整条发言框会换成一行
「已归档（只读）」提示 —— `开局` 按钮、dsh-chat 自己的 `@all` / `@成员` 那一排都一并不出现。
判据就是 dsh-chat 的 `coldStored`，两侧各拦一道（dsh-chat 补丁 23 + 庄家自己），
所以即使 dsh-chat 的补丁被插件升级冲掉，老房间里也不会长出按钮。

**先讲清机制**：dsh-chat 里真人在房间中的"身份"就是**房间自身的会话**
（`dsh-chat-room-v3-<房间id>`，房间视图里显示为 You），而房间视图接管了输入框（**不走 slash 命令**）
—— 所以 2026-10-04 之前，真人必须另开一个"信箱会话"收夜聊、用 `/ww-reply` 回话。

**v1.11.0 起不需要了**（前提：dsh-chat 打过**补丁 21**，见 `PATCH-NOTES-dsh-chat.md`）：

- **开局/状态/催人/回话等 `/ww-*` 命令，直接在房间发言框里打**：庄家在消息**落盘之前**把它拦下来执行，
  并把这条消息**吞掉** ⇒ 房间里不会出现命令正文，AI 谁也看不见。
- **庄家给你看的私密内容（发牌、验人结果、夜序提问、命令回执）走屏幕正中的浮层弹窗**
  （v1.16.6 起居中；此前固定在右下角，会和别的插件界面打架），
  **不进任何会话**（比放信箱更干净：连"进了会话、模型读得到"的可能都没有）。**通知卡**看完点「知道了」收起；
  **提问卡 / 确认卡 / 投票卡（带按钮的必答卡）没有「知道了」**（v1.31.0），点按钮答完才收起。没看过的下次还会再弹。
- 真人席位写成 **`*名字`** 即可（不必再写 `=会话`）。

步骤：

1. **开局**（在房间发言框里直接打，或者让你的观察员会话打斜杠命令 —— 两种都行）：
   ```
   /ww-start AI狼人杀3 4 *千野 大D 小米 大G
   ```
   `*` 前缀 = 真人席位，**不写 `=` 就是弹窗模式（推荐）**。
   想沿用老玩法（把私聊投进某个会话）就写 `*千野=千野`（后面是那个会话的标题或 id）；
   标题重名时改用会话 id（先 `/ww-sessions 关键字` 查「标题 → id」，重名的带 ⚠ 标记）。
   绑定不合法（绑了房间自身会话、绑了不存在的会话）或**弹窗模式能力不可用**时，开局会直接报错并告诉你怎么改。
2. **夜间**：庄家把发牌/提问推到你屏幕上的**浮层弹窗**里（通知卡点「知道了」收起；提问卡点按钮作答，答完自动收起）；
   房间里**不出现**任何牌面或夜聊。
3. **你回话**：**提问卡上直接有按钮**（v1.14.0，点着答就行）——
   预言家：「查看未分配的 2 张牌」+ 每个其他座位一个「验 ×××」；
   怪盗：「不换」+ 每个其他座位一个「换 ×××」（不能换自己）。
   点一下按钮 = 把那个选项的答案交给庄家，那张卡随即收起、下一个问题自己冒出来。
   想手打也完全可以（**保底不变**，两条路在庄家那边是同一个入口）：
   ```
   /ww-reply 换 小米      （或：/ww-reply 验 大D ／ /ww-reply 2 ／ /ww-reply 不换）
   ```
   这条命令同样被拦下执行、不进房间（回执走浮层）。**在房间里打 `/ww-reply` 是安全的** ——
   前提是补丁 21 装好了；没装的话插件会**拒绝你开局**（不许你在没保护的房间里说夜话）。
   ⚠ 按钮只出现在**弹窗模式**（`*名字`）的提问卡上；老玩法（`*名字=<会话>`）与 AI 席位照旧走命令/工具。
5. **白天发言与投票仍在房间里做**：你的房间发言（作者 = 房间自身会话）会被自动算成你的席位。
   轮到你时**发言框上方会出现一条只读前缀**（`【R{轮}-{序号} · 你的席位名】` + 点名对象）——
   v1.10.1 起**不再有私聊提醒**，看那条前缀条就够了；你**只打正文**，前缀与点名由庄家在落地前补好
   （见 §3 的 v1.10.0 说明）。**投票（v1.15.0 起有按钮）**：收票时弹窗里会给一排按钮 ——
   `投 ×××`（每个其他座位）+ `投 平安夜`，**点一下就代替手打**；想手打照旧
   （`投票：<名字>` / `投票：平安夜`，原文一个字不动、也不接管）。两种方式等价：点按钮就是
   **以你的房间身份**把同一串字发进房间（票照旧是公开消息；**提及与 AI 的票同款 `@all`** —— v1.29.1 修：早先真人票的提及是空的，AI 会话一条都收不到）。
   ⚠ **一票落定（v1.18.0）**：投出去就定下、不可撤改 —— 重复投同一票不会重复计票，改投会被**静默忽略**
   （庄家只在审计里记一笔，房间不回话）。真人本来也跟不上 AI 的速度，通常是最晚投的那个，投完就结算。
   ⚠ **投票阶段不计时（v1.30.0）**：旧版"2 分 30 秒催票 / 2 分 30 秒记弃权"那一套**已关掉**（新规则卡去掉了限时）。
   你可以想多久都可以 —— 收票不会因为你慢而自动结算；真卡住了让观察员 `/ww-close-vote` 收口。
   ⚠ **不能投给自己（v1.20.0，真人同理）**：手打"投票：你自己"会被判无效，庄家**私聊**让你重发（弹窗里那排按钮本来就不含你自己）；
   你自己在房间框里打的那条**已经公开、撤不回** —— 所以房间里会看到一条，但它不计票。自投不落定，重投照常算。
   ⚠ **不能弃票（v1.30.0，与 v1.25.0 相反）**：新规则卡「非失联者不得弃票/弃权」⇒ 你发「弃票」会被**打回**，
   庄家私聊（弹窗）告诉你"不能弃票/弃权"并列出可选目标；**票不落定，重投照常算**。**投票卡上也没有弃票按钮了**。
   （只有失联者由观察员代记弃票 —— 那是房间外的动作。）
6. **信箱会话不要拉进房间**（房间里也不能有第二个同名成员——庄家开局会校验并拒绝）。庄家认的是开局绑定
   （`*千野=千野` 按标题/id 解析），跟成员名单无关；作为补偿，庄家开局会在房间里给你注册一个
   **同名"聋占位成员"**（`werewolf-human-seat-<房间id>-<座位号>`，不指向任何真实会话）：
   AI 万一点名你，消息照样落时间线、该轮照常推进，而那笔投递必然失败并被 dsh-chat 按收件人吞掉，
   **不会唤醒任何会话**；对局结束时占位成员自动撤掉。
7. **提及规则**：轮到你时 AI 只写 `mentions = ["all"]`，开场公告会写明"真人席位是 X（房间视图里的 You）"。
   **点名你其实已经无害**（没有会话会被唤醒、也不泄露），但**对你没有任何通知效果**（点名落在一个聋占位上），
   而且占位成员不在时（两局之间）点名会让那条发言整条发废——所以纪律保持"不点名"。
   你这一棒的提及（`["all", 下一位]`）**由庄家在发言落地之前算好**：你不用 AT 任何人、也不用写前缀。
   轮到你时靠发言框上的前缀条（v1.10.1 起不再私聊提醒）；真卡住了可以让观察员 `/ww-nudge` 催一次。
7. 房间时间线里**永远不出现**夜聊内容（夜聊只在你的浮层弹窗里）。

**沿用老玩法（信箱会话）**：写 `*名字=<会话>` 即回到 v1.10 的行为 —— 私聊投到那个会话、
在会话里用 `/ww-reply` 回话；缺点是要多开一个会话、且命令不进房间。
弹窗模式不可用时（补丁 21 没打），这是唯一的玩法。

多个真人：每人一个 `*名字` 席位；但**同一个房间视图只能对应一个真人席**
（房间里的发言都来自同一个房间会话，弹窗模式还会让两个真人撞同一个身份）⇒ 第二个真人需要
另开自己的房间视图会话才能独立发声。

### 真人席位的使用要点（首轮测试踩出来的；v1.7.1 起为可见卡片）

- **v1.16.12：卡片也覆盖"静默投递"的第二条通道**。dsh-bridge 的 `wake:false` 有两条落地方式：
  ① 落表面（`surfaceOp: 'append'`，会话闲置时）—— 官方不渲染，一直由我们的卡片补；
  ② **进 `next-step` 队列（`Agent.inject`，目标正在跑回合时）**—— 官方 `messageDefinition.match()`
  要求 `isAppendSurfaceEvent(event)`，**也不渲染它** ⇒ 现在也由我们的卡片补上
  （判定挪到 `start()`：能读 inbox claim 状态区分"该我们画"与"官方会画 `turn-trigger`"）。
  ⚠ 代价：**卡片会迟到**——它随消息被 claim 的那一刻出现（目标 idle 时是下次唤醒那轮，非 idle 时是当前那轮）；
  未 claim 期间消息只在 inbox 里、没落盘，客户端根本收不到事件。
  ⇒ 好处：事后单独翻某个 AI 会话的复盘时，**能看到当时的消息窗口**（用户 2026-10-05 的诉求）。

⚠️ **关键事实（表述在 v1.7.1 修正）**：官方 UI 的可见性判据（`dsh-client-ui-chat/lib/client.js`
`isVisibleChatNode()`）把**任何非 `user` 来源的普通文本消息**归成 `context` 行并**排除在可见 Chat 行之外**
（注释原文：*"Exclude system prompts, ordinary Context, and permission commands from visible Chat rows"*）。
⇒ 庄家投给真人的私聊**确实在会话里、模型也读得到，但官方渲染器不画它**。

**v1.7.1 的处置不是改官方 UI，而是插件自己注册节点**：`client.js`（客户端半边）注册了一个
事件定义 + `conversation.chat.node` 渲染器 —— 私聊在**真人自己的会话里就是一张可见卡片**
（标题「📨 庄家私聊」+ 正文 + 「用 `/ww-reply <回答>` 回复」），它是独立行、不会被折进回合。

⚠️ **卡片只画"官方本来就看不见"的那一类（v1.7.7）**：判据是事件带 `surfaceOp === "append"`，
即「只落表面、不唤醒」的投递（真人席位全是这类）。会**唤醒**的私聊（`wake:true`）官方自己会画
成「收到执行请求」的回合触发行，所以插件不重复画——否则同一个消息会出现两个气泡
（2026-10-04 真机：狼的发牌"只有一个信息，却有两个气泡框，两边发言一模一样"）。

```
📨 庄家私聊                                     12:03
你的角色卡是狼。这局你有个同伴狼是小米。本条无需回复。
【怎么知道轮到你】**被唤醒就是轮到你** ……（v1.16.5 起的唤醒口径；**v1.20.1 把"被 @"改成"被唤醒"**，全文见 `lib/templates.js` 的 `WAKE_RULE`）
──────────────────────────────────────────────
用 `/ww-reply <回答>` 回复
```

命令仍然是可用的、也是**唯一能"主动取回"**的信道（卡片只在页面里显示，命令结果能落进会话日志）：

```
/ww-status     查看阶段；若庄家在等你，会直接贴出待答原文
/ww-inbox      取回庄家发给你的全部夜聊原文（发牌/同伴/提问/读数/换卡结果）
/ww-reply <回答>  回答（例：/ww-reply 换 小米、/ww-reply 2、/ww-reply 不换）
```

**升级后要做的两步**：重启 DSH（`dsh.client` 的扫描结果是**进程级缓存**，见 `VERIFICATION.md`
「客户端半边」一节，只开关 bundle 不重新扫描）→ 刷新页面。效果可自检：卡片带
`data-dsh-werewolf-mail` 属性，正文里不会出现 `[dsh-bridge …]` 桥接信封行。

另外两点口径要说清：

1. **`wake:false` 只保证"不因投递而唤醒"，不等于"不进模型上下文"**：私聊落在会话表面上，
   你自己的会话一跑任何回合（**包括你敲命令**），那一回合的模型就会读到夜聊原文（首轮测试里
   模型确实读到了"我是狼、同伴是小米"）。跨玩家保密仍然成立（信箱会话不是房间成员、其他玩家读不到）。
2. **开局回执与 `/ww-status` 会报投递结果**：`开局私聊：成功/本批条数 已投递`／`⚠ 未送达`，用来区分"没发"与"没到"。
   注意分母是**本批实际发出的私聊条数**（发牌 + 夜序第一条提问），不是玩家人数——发牌只发给狼与村民。

## 4. 隐私模型（本插件的存在前提）

| 数据 | 落在哪 | 会不会被会话读到 |
|---|---|---|
| 牌面映射、夜聊原文、换卡、票型、结算 | `%APPDATA%\dsh-werewolf\{房间id}-第N局.json` + `.audit.jsonl` | 不会（工作区之外、非记忆文件） |
| 夜间私聊 | 只投给该玩家的会话时间线 | 其他玩家不可读 |
| 赛后 raw | `狼人杀复盘\_raw\<YYYY>\<MM>\<YYYYMMDDHHMM>_第X局.md`（普通文件，不参与记忆注入） | 结算后才有，观察员自取 |
| `.dsh-memory` / `MEMORY.md` / `AGENTS.md` | **从不写入** | — |

插件源码里**没有任何**房间落盘读取调用（`chat.messages` / `chat.history` / `rooms.json`），
投票期间只用开局的实时事件流 —— 见 `test/acceptance.test.mjs` 的运行时探针 + 静态检查。

## 5. 实现的判据（规则卡留白处的显式选择）

规则卡与需求说明在少数分支上留白，本插件按下表实现，全部有测试覆盖：

| 场景 | 选择 | 依据 |
|---|---|---|
| AI 席位的回话通道 | 把 `wolf_reply` 提示**附在提问那条私聊上**（提问/复问/夜间提醒） | 工具表里有工具≠模型会用；不提就会在自己的会话里回一句，庄家收不到 |
| 真人的回话通道 | 同位置附 `/ww-reply` 提示 | 真人不能调工具，只能走人类命令 |
| 真人席位的私聊 | `wake:false`（只落时间线、不唤醒）+ 附信道提示 | 唤醒会跑该会话的模型回合，夜聊就进了 LLM 上下文 |
| 真人私聊的**可见性** | 插件自带 producer kind（`plugin:dsh-werewolf-dealer`）+ 客户端半边注册 `conversation.chat.node` 渲染器 | 官方渲染器把非 `user` 来源的消息归成 context 行并隐藏；不改官方包就只能自己注册节点（形状照抄 dsh-chat 的广播卡片） |
| 真人席位的房间侧身份 | 自动接受房间自身会话 id 作为该席位的作者 | dsh-chat 客户端用 `sessionId` 当 author |
| 房间提及里的真人 | 一律**不**点名（前缀条负责告知轮次） | 点名落在一个聋占位上：对真人没有通知效果，占位成员不在时还会让整条发言发废 |
| 催人怎么催 | **只由人触发**（`/ww-nudge`），自动提醒保持关闭 | 时间阈值量的是"思考时长"，本机 mimo 会想 54 分钟；谁该动由状态机判（`#pendingActions`），不靠时间猜 |
| 催人报告 | 附每个被催会话的实时状态（空闲/正在运行/离线…） | 让观察员分清"在长思考"与"真卡住"，这是不能用计时器之后必须补的信息 |
| 房间已有同名成员 | 开局**拒绝**并让人先移出房间 | 两个同名成员会让 dsh-chat 的提及解析判歧义，那条发言整条发不出去 |
| 轮到真人发言 | **不私聊提醒**（v1.10.1 起）：他看房间发言框上的只读前缀条 | 排班靠提及唤醒，真人不在唤醒链上；每轮再投一条既重复、又把信箱会话顶到侧栏最上面。需要人工催时仍有 `/ww-nudge` |
| 真人的私密内容（v1.11.0） | **弹窗**：写进 `<gameId>.mail.jsonl`，由 `/api/dsh-werewolf` 的 `inbox` 端点吐给浏览器，`shell.overlay` 画成浮层 | 秘密**不进任何会话**（比"投给专用会话"更干净）；代价是没有持久留痕 ⇒ 未读队列 + 「作答/确认后才推进游标」+ `/ww-inbox` 重弹。**v1.31.0：必答卡没有「知道了」**（误点它会把题永久丢掉、确认阶段整局停住），只有被庄家拒收后才给「关闭这张卡」 |
| 弹窗里的**提问按钮**（v1.14.0） | 邮件记录多带一个 `options: [{label, text}]`；前端把这张卡画成一排按钮，点了 `POST /api/dsh-werewolf` 的 `reply` 端点 | **`text` 就是引擎认识的那串答案**（与手打 `/ww-reply` 同一文法）⇒ 按钮与命令是**同一条入口**、行为必然等价，命令保底永在；只有提问卡带 `options`，发牌/读数/回执照旧只有文字（v1.16.13 起 **AI 席位**的读数/换执/复问连私信都不发了，直接随 `wolf_reply` 返回值给出；**真人席位**仍走这张卡） |
| 弹窗里的**投票按钮**（v1.15.0） | 投票卡带 `channel: 'room'`：点按钮走同一个 `reply` 端点，但庄家**以他的席位身份**把 `投票：××` 发进房间 | 票必须是**公开消息**（AI 的票也是房间消息，大家看得见），所以不能走夜间私聊入口；发进房间后照旧由 `onRoomMessage` → `parseVote` 收票，**没有第二条解析路径**；卡片的 channel 与当前阶段不符（陈旧卡片）一律拒收；**真人的票与 AI 的票同款提及 `['all']`**（v1.29.1：手打那条入口也一并补）—— 只把票投进成员会话的上下文，**不唤醒谁** |
| 房间里的 `/ww-*`（v1.11.0） | 庄家在**落盘之前**拦下执行，并让 dsh-chat **吞掉**这条消息 | 命令正文进房间就是当众泄密（`/ww-reply 换 小米`）；吞掉依赖 dsh-chat 补丁 21，**探测不到就不拦、也拒绝弹窗模式开局** |
| 真人席位写法（v1.11.0） | `*名字` = 弹窗模式；`*名字=<会话>` = 老玩法 | 前者不需要额外会话；后者保留（补丁 21 缺失时的唯一玩法）。绑房间自身会话仍然拒绝 |

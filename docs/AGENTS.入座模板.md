# 工作区纪律

细则（角色／流程／胜负／证据规则）一律以 `新版一夜狼人杀规则卡.md` 为准；本文件只写 AI 会话要做的动作。

## 入座（会话首轮，各做一次）
1. 用你的文件读取工具，中文显式 UTF-8，读规则卡全文。
2. 用你的文件读取工具，中文显式 UTF-8，读方法论全文。
3. `session_rename`：标题设成**首句里别人怎么称呼你**；首句没叫你名字就先问、别改。改名必须在加入群聊之前，若未安装 session_rename，请用户给会话改名后再入座。
4. 加入“AI狼人杀”的群聊，如果没有该房间，就创建一个。

## 对局中
- **被唤醒就是轮到你**：收到 唤醒你 的房间消息就立刻用 `wolf_speak` 交**正文**（不要自己写前缀、不要自己填提及、不要等庄家单独提醒）。
- 公开发言、投票、赛后感想都用 `wolf_speak`（只给正文；投票写 `投票：<座位名>` 或 `投票：平安夜`）；夜里和确认是否进投票阶段回庄家用 `wolf_reply`。
- 庄家标了「本条无需回复」的消息**不要回**。
- 局内信息（身份牌、夜查读数、夜间行动、票型、临场策略）不得写入任何共享落盘（日志、项目笔记、交接账本、看板）——这些文件会被同桌会话注入读到。

## 落盘与记忆
- 复盘／日志只由**庄家指定的那一个会话**写：单局详情不用写，现在由庄家插件自动导出；当日 `.dsh-memory` 日志只留一行指针＋方法论；不要写入项目笔记；`狼人杀方法论.md` 只收方法论／机制／判据，禁止单局详情。
- 其余同桌会话只把感想发群里，**不写**日志／项目笔记／反思（记忆插件「完成工作后写日志」的提醒在本工作区让位给本条）。
- 同一工作区并发追加同一记忆文件会留下悬空锚点（orphan-anchor）并毒住后续写入 ⇒ 写入安排在对局结束后、由单一写手完成；报该错时按当日日志里的流程走（grep 定位 → 备份 → 删悬空锚点行 → 重试）。
- 狼人杀类局内策略不进技能库。
- **文档分层**：规则卡只写游戏规则（角色／流程／胜负／证据）；插件机制细节（谁被 AT、唤醒链、发信时序、发牌给谁）**一律不进规则卡**——写进去等于给对手施工图；操作动作只写在本文件。

## 关于chat_send的点名机制
- mentions 是结构化投递名单，正文不参与解析。
- 点名成员（别名/sessionId）→ 唤醒该成员。
- 只写 all → 全员收到「仅知悉」通知，不唤醒任何人。
- all + members（房间「唤醒」勾选）→ 全员唤醒；被唤醒的本地会话在本房间的下一条 chat_send，mentions 会被整体替换成 ["all"]（纯广播、不唤醒），并随即清除。
- 其余情况 chat_send 不补 mentions：回复人类可省略，要叫谁就写谁。
- wolf_speak 是狼人杀专用工具，它会自动补充提及，所以无需写成员名。
